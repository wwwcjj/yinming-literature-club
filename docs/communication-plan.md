# 文学社信息架构方案

> 记录时间：2026-08-27
> 一句话总结：**企业微信管群 = 活动管理；网站 = 讨论与内容沉淀。**

## 背景与痛点

- 文学社有一个几百人的大群，新生进群只能靠管理员**手动一个一个拉**，效率低、易遗漏。
- 为了容纳更多人数而拆成多个群，又担心**讨论被分散**。
- 结论：把「即时通知」和「内容讨论」分成两个信道，各司其职，互不干扰。

## 双信道分工

- **微信群（企业微信管理）＝ 管理信道**：活动通知、报名接龙、现场沟通、新人引导。特点是即时触达，消息看过即走。
- **网站（GitHub Pages + Waline 讨论区）＝ 内容信道**：读书讨论、原创作品、书评、活动回顾。特点是可沉淀、可搜索、长期保存。
- 原则：**群里不做深度讨论，讨论统一搬到网站。**

## 微信群方案：企业微信 + 群活码

- 使用企业微信「群活码」：新生扫一个二维码**自动进群**，群满 200 人**自动开新群**，管理员零操作。
- 完全免费、官方产品，无需营业执照（未认证状态即可用）。
- **为什么不用 500 人/群**：500 人上限需要企业认证（营业执照 + 对公账户打款验证），学生社团无法认证；且认证后群超过 200 人，扫码进群仍需群主手动确认，自动化优势消失。
- **为什么不用 QQ**：不使用 QQ 作为主阵地。
- **重要通知**：用「群发助手」一键广播到所有客户群 + 置顶群公告。
- **老群迁移**：每个群的置顶公告里放最新群二维码，想继续活跃的成员扫码进当前群。
- 人数余量：未认证企业外部联系人总上限 1000 人，对几百人的社团绰绰有余。

## 网站方案：GitHub Pages + Waline 讨论区

- 网站现状：GitHub Pages 纯静态站（index / about / works）。
- 讨论引擎选型：**Waline**（免费、专为静态站设计）。
  - 后端：Vercel 免费额度，GitHub 账号登录一键部署，无需自建服务器。
  - 数据：LeanCloud 国际版免费额度。
  - 前端：几行 JS 嵌入现有静态页面。
- 分区构想（每个页面一个分区，一套系统）：
  - **公告**：社团通知、活动预告
  - **读书讨论**：共读书目、读后感
  - **原创作品**：小说、诗歌、散文投稿与展示
- 登录方式：邮箱注册即可，社员零门槛。
- 管理：Waline 后台可删帖、置顶、设置话题。
